# AI 모드 QA 도구 사용법

## 실행 환경

Unity Editor 메뉴에서 연다. 별도 씬 오브젝트나 컴포넌트 추가는 필요 없다.

- `Tools > AI QA > ItemOffer 지정`
- `Tools > AI QA > AI 판단 모니터`

두 기능은 Editor 전용이며 플레이어 빌드에는 포함되지 않는다. ItemOffer 지정은 AI 모드의 MasterClient에서만 적용한다. 기존 `PlayerManager > QA 시작 아이템`은 시작 인벤토리 구성에 그대로 사용한다.

## ItemOffer 지정

1. 플레이 시작 전 또는 진행 중 창을 연다.
2. 사람·AI 각각 원하는 대상의 `지정 활성화`를 켠다.
3. 이름 또는 ID로 검색해 서로 다른 아이템 3개를 고른다.
4. `설정 저장 / 다시 예약`을 누른다.
5. 다음 해당 대상의 **제안 생성 시점**에 지정값을 사용한다. 이미 생성된 현재 선택지는 바꾸지 않는다.

기본은 다음 1회 적용이다. `반복 적용`을 켜면 이후 해당 대상의 제안도 계속 지정한다. `특정 TurnIndex만`은 전역 TurnIndex와 정확히 일치하는 생성 요청만 지정한다. 특정 TurnIndex가 지났거나 해당 턴에 인벤토리가 가득 차면 적용되지 않으므로 다시 예약한다.

사람·AI 설정은 독립적이다. 창을 닫아도 저장한 예약은 유지된다. 같은 Editor 세션의 Play 재시작 및 새 방에서는 1회 예약을 다시 준비한다. Editor를 종료하면 설정은 초기화된다. `지정 해제`는 이후 생성을 기본 추첨으로 돌리며, 이미 제공된 선택지를 소급 변경하지 않는다.

정상 모드는 현재 아이템 공급 필터, 등급·아이템 가중치를 준수한다. AI 모드 제외 아이템인 3001·4006과 보상 전용 5000 등은 거절한다. `QA 강제 지정`은 이 공급 제한을 우회한다. 강제 모드도 ItemDB 등록·3개 고유 ID·인벤토리 만석 처리는 유지한다. 이 기능은 상점 목록을 변경하지 않는다.

유효하지 않은 예약이면 상태에 거절 사유를 표시하고 기본 추첨을 사용한다. 1회 예약은 실제 지정 성공 전에는 소모하지 않는다. 만석에서는 기존 FULL_INV 처리를 유지한다. 최근 지정·거절 기록은 50개까지 표시한다.

## AI 판단 모니터

1. 창 상단의 `기록 수집`을 켠다.
2. AI 턴을 진행한다.
3. 제안 선택·인벤토리 사용·훔치기 판단 이력을 선택한다.

기록 시점의 Actor·TurnIndex·Wave, 기력·예산, HP·방어막, 후보 ID·UID·비용·점수·제외 사유·최종 선택을 확인할 수 있다. 인벤토리 사용은 효용·기믹·정화 점수, 훔치기는 효용·기믹 점수를 함께 표시한다. 제안 선택은 실제 총점을 표시한다.

기력 부족·예산 초과·사용 제한으로 거절한 후보는 `미평가`로 표시한다. 모니터 표시를 위해 효용을 추가 평가하지 않는다. 예산도 원래 경로에서 계산하지 않았다면 `미계산`으로 표시한다. 만석·락픽 없음 등으로 단계를 생략한 이유도 기록한다.

`최종 선택`은 AI의 판단 결과다. 아이템 사용 성공, 락픽 성공, 인벤토리 이전 완료와는 구분한다. 실제 공격의 피해 배수·피해량·방어막 전환 결과는 `실제 공격 결과` 기록에서 확인한다. 마을 업그레이드 판단은 수집 범위에 포함하지 않는다.

최근 판단 200개를 보관하며 Play 시작 시 비운다. `기록 수집`을 끄면 새 기록만 중단한다. 이력을 클릭하면 최신 따라가기를 해제해 내용을 고정한다. Actor와 판단 종류로 필터링할 수 있고 `JSON 내보내기`는 필터와 관계없이 보관 중인 전체 이력을 저장한다.

스크립트 재컴파일·도메인 리로드 시 메모리의 판단 이력은 초기화된다. 필요한 기록은 먼저 내보낸다.

### 아이템 사용 후 배수 확인

모니터 오른쪽의 `현재 전투 효과`에서 선택한 Actor(필터가 전체이면 AI)의 값을 확인한다. 과거 이력의 스냅샷과 현재 값은 별도로 표시한다. 행동 제어·사용 예약 창에서도 현재 전투 효과를 볼 수 있어 공격 직전에 대기시키고 비교할 수 있다.

- **공격 피해 배수**: 기본 공격에 곱하는 값. 예: 날 갈기 1개는 ×1.5, 2개는 ×2.25. 무작위 원본 피해 덮어쓰기는 가능한 두 결과를 표시한다.
- **피해 → 방어막 전환율**: 기본값·덮어쓰기·보정과 최종 비율. 예: 은도금 100%에 저주 -15%p가 있으면 85%다.
- **방어막·기본 방어력 / 마을 피격 배수**: 현재 방어 수치와 나무 공격에 곱하는 배수를 구분한다. 예상 마을 피해는 `최대(0, 나무 공격 × 피격 배수 - 방어막 - 기본 방어력)`이다.
- **마을 진입 대기 효과**: 첩자의 방어막 ×0.7처럼 나중에 적용되는 효과는 현재 방어막과 분리해 표시한다. 기본 방어력에는 곱하지 않는다.

`효과 출처·중첩 상세 표시`를 켜면 상태 ID·배수·출처 Actor·잔여 횟수를 확인한다. 조회는 상태를 소모하거나 난수를 추첨하지 않는다. 산성비처럼 즉시 방어막을 바꾸는 아이템은 현재 방어막에 반영되며 지속 배수로 표시하지 않는다.

`기록 수집`을 켜면 `아이템 사용 후`, `전투 수치 반영`, `실제 공격 결과` 이력이 추가된다. 아이템 처리 알림 시점에는 네트워크 프로퍼티 갱신이 지연될 수 있으므로 방어막·피격 배수는 후속 `전투 수치 반영` 기록으로 대조한다. `실제 공격 결과`에는 실제 계산에 사용한 원본 피해·배수·전환율·최종 피해·방어막 획득량을 저장한다. AI 시뮬레이션은 제외하며, 실제 공격을 수행한 Actor의 결과가 기록된다. 스냅샷과 확정값은 JSON 내보내기에도 포함된다.

현재 전투 효과는 기본 공격과 현재 나무 공격 기준의 미리보기다. 이후 상태 변경·밤 전환으로 달라질 수 있으며, 미지원 상태는 별도로 표시한다.

## 빠른 확인 예시

AI 제안을 `1000 날 갈기 / 1002 연속 베기 / 3000 응급 수액`으로 예약하고, 모니터의 기록 수집을 켠다. AI 턴에 예약 상태와 현재 OFFER, 제안 선택 총점을 확인한다. 이후 인벤토리 단계에서 기력 예산과 임계값 때문에 사용이 달라지는지 비교한다.

## 검증

`AIQAToolChecks.Run()`은 Play Mode 밖에서 실행하는 독립 검사다. 등록·제외·중복 ID 검증, 강제 지정 범위, 1회·반복·특정 턴 예약 조건, 임계값·동점·제외 사유, JSON 스냅샷 보존, 난수 비소모를 검사한다. 씬·방 프로퍼티를 변경하지 않는다.

`AIQACombatChecks.Run()`은 실제 아이템 데이터로 배수 중첩·은도금/저주 전환율·무작위 덮어쓰기·첩자 대기 효과·방어 계산을 검사한다. 복제한 상태에서 실제 이벤트 처리 결과와 비교하고, 반복 조회의 상태/난수 비소모 및 JSON 보존도 확인한다. 실제 경기 전체 진행 검증과는 구분한다.

## AI 행동 일시정지·아이템 사용 예약

메뉴: **Tools > AI QA > AI 행동 제어 · 사용 예약**

### 단계별 진행

1. `QA 제어 활성화`를 켠다.
2. `대기할 단계` 또는 `모든 단계에서 대기`를 고르고 `중단점 설정 적용`을 누른다.
3. AI가 해당 단계에 도달하면 이 창에서 Actor·TurnIndex·대기 위치를 확인한다.
4. `현재 단계 진행`은 그 지점을 재개한다. `다음 단계까지 진행`은 재개 후 다음 체크포인트에서 다시 대기한다.

체크포인트는 제안 선택 전, 첫 훔치기 전, 자기 인벤토리 도착 후, 두 번째 훔치기 전·후, 두 번째 도난 성공 후 추가 인벤토리 도착 시, 공격 직전이다. 추가 인벤토리 단계는 두 번째 도난이 성공한 경우에만 도달한다. 이미 지난 단계를 소급 실행하지 않으므로 필요한 예약은 미리 저장한다.

Unity 전체를 멈추는 기능은 아니다. `대기 중 턴 타이머 정지`를 켜면 QA가 대기하는 동안 남은 턴 시간을 보존한다. 재개 시 같은 턴의 타이머만 복구하며, 다른 기능이 이미 정지시킨 타이머를 임의로 재개하지 않는다. 시간 만료를 시험할 때는 이 옵션을 끈다.

### 자연 판단 관찰과 강제 사용

사용 예약에서 아이템·시점·방식을 선택하고 `사용 예약 저장 / 다시 예약`을 누른다. `QA 제어 활성화`가 켜져 있어야 실행된다.

- **자연 판단 관찰:** 해당 시점 도달을 기록하고, 선택했다면 먼저 대기한다. 아이템을 보관하거나 사용시키지 않는다. 이후 자연 행동과 판단 모니터로 결과를 확인한다.
- **강제 사용:** 지정 시점에 보유 아이템 사용을 요청한다. AI의 점수·턴별 기력 예산 판단만 우회하며, 실제 기력·현재 턴·사용 제한·보유·대상 조건은 기존 슬롯/InventoryAuthority 경로에서 검증한다. 아이템·기력을 자동 지급하지 않는다.

기본은 다음 해당 단계 1회 시도다. `매 턴 반복` 또는 특정 전역 TurnIndex로 제한할 수 있다. 사용 UID가0이면 해당 종류의 첫 보유품을 사용한다. UID를 입력하면 정확히 그 복제품만 선택한다. 제물 바치기는 별도 제물 UID를 지정하거나0으로 두어 낮은 효용의 다른 보유품을 선택하게 할 수 있다.

강제 사용 예약품은 해당 턴의 자연 사용·자동 제물 후보에서 보관한다. UID가0이면 같은 종류의 복제품도 그 턴 동안 보관하므로 예약 직후 자연 사용으로 추가 소모되지 않는다. UID를 지정하면 다른 복제품은 자연 사용될 수 있다. 특정 미래 턴만 예약했다면 앞선 턴에는 보관하지 않으므로 그때 사용돼 없어질 수 있다. 한 번 적용된 단발 예약의 보관은 다음 턴에 해제된다.

### 결과 확인·해제

실행 이력은 `사용 확인 / 거절 사유 / 요청 후 확인 불가 / 취소`를 구분한다. 사용 확인은 기존 권한 경로의 효과 처리 알림과 해당 UID 소모를 함께 확인한 결과이며, 피해 수치·연출의 정상 여부는 게임 화면과 전투 로그로 별도 확인한다. 요청 후5초 이내 처리 알림을 받지 못하면 확인 불가로 남긴다. 거절·확인 불가도 해당 시도의 종료이며 자동 재시도하지 않는다.

`모든 예약 · 대기 해제`는 미실행 예약과 중단점을 끄고 대기를 해제한다. 이미 보낸 사용 요청·처리된 효과를 되돌리거나 환불하지 않는다. 창을 닫는 것만으로 설정이 해제되지는 않는다. 예약 설정은 Editor 세션 동안 유지되며 Play 시작·새 방에서는 단발 예약을 다시 준비한다. 재컴파일 시 대기와 메모리 이력은 해제된다. 플레이어 빌드에는 이 기능이 포함되지 않는다.

예: 공격 전에 신의 가호를 반드시 쓰는 효과 시험은 `대기할 단계=중단점 없음`, `예약 시점=나무 공격 직전`, `아이템=4009`, `강제 사용`, `예약 시점에서 먼저 대기`로 설정한다. AI에게4009와기력7 이상을 미리 준비하고, 공격 직전 대기에서 상태를 확인한 뒤 `현재 단계 진행`을 누른다. 자연 정화 판단을 시험할 때는 강제 사용 대신 관찰 방식을 사용한다.

`AIQAActionChecks.Run()`은 단계·턴 조건, 단발·반복, 예약품 보관, 자연 관찰의 비개입, UID 선택과 결과 구분을 검사한다.
