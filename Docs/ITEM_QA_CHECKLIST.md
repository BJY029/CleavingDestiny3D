# ITEM QA 체크리스트

작성 기준: 2026-11-17 / CleavingDestiny3D 작업 디렉터리의 현재 소스와 에셋.

아이템 SO 27종과 `Assets/Localization/Item_CSV.csv`를 대조하고 실제 사용, 상태 효과, 피해 계산, 미니게임, 신약 미션 코드를 추적한 테스트 계획이다. **플레이 테스트는 수행하지 않았으며 모든 항목은 미실행이다.** 코드에서 확인한 현재 동작이 곧 기획상 정답이라는 의미는 아니다. 불일치 항목은 아래 이슈 표와 연결해 판정한다.

## 1. 실행 및 판정 방법

- 체크박스는 실행 완료 표시다. 실제 판정은 문서 마지막 실행 기록표에 `통과 / 실패 / 차단 / 해당 없음`으로 남긴다.
- P0: 중복 적용·아이템 유실·진행 불가·승패 오류. P1: 효과·대상·수치·지속·제한 오류. P2: 문구·아이콘·연출 오류. 별도 표기가 없는 항목은 P1이다.
- `현재 구현`은 소스로 예상한 관찰값이다. `요구`는 QA 합격 조건이며 현재 소스와 다를 수 있다. 기획 미확정 사항은 `기획 확인`으로 남기고 임의로 통과시키지 않는다.
- A=아이템 사용자, B=상대. 기본 검증은 PvP 클라이언트 2개로 하고 Master=A/B를 바꿔 반복한다. AI 모드는 별도 검증한다.
- 매 케이스는 새 상태에서 시작한다. 평타 원본 피해 D=100, 기본 전환율 R=0.30, A 방어막=100, B 방어막=1000을 권장한다. D와 R은 실제 방 설정·업그레이드·날씨 영향을 제거하거나 기록하여 맞춘다.
- 나무 HP는 회복/공격 후에도 게임이 종료되지 않을 만큼 충분히 준비한다. 기력은 비용 이상으로 설정한다. 중복 사용 테스트는 동일 아이템 복수 소유가 필요하다.
- 관찰값: 사용 전후 기력, 아이템 ID/UID와 슬롯, 나무 HP, 양측 VillageHP/VillageBarrier, 상태 소유자·출처·중첩·잔여, TurnIndex/CurrentWave/현재 Actor, UI·전투 로그·예외 로그.
- 랜덤 결과는 시드와 시행 수를 기록한다. 두 결과가 나오지 않았다는 이유만으로 짧은 표본에서 확률 오류를 확정하지 않는다.
- 게임 코드를 바꾸지 않고 실행 가능한 QA/디버그 수단을 사용한다. 특정 아이템 강제 지급 등이 불가능하면 해당 케이스는 준비 조건 때문에 차단으로 기록한다.

## 2. 동작 구조와 계산 기준

일반 사용은 `InventoryAuthority.RPC_UseItem`이 낮·자기 턴·사용 제한·기력·일부 대상 조건을 검증한 뒤 기력을 차감하고 슬롯을 비운다. 이어 `ItemHandlingSystem.AddItemStatusInstance`가 제한을 기록하고 즉시 효과 또는 상태를 적용한다. 락픽·잠금·연기·도박·제물은 별도 분기가 있다. 따라서 효과 처리 실패 시에도 이미 비용이나 아이템이 소모되는지를 확인해야 한다.

- 일반 피해: `RoundToInt((덮어쓰기 피해 또는 D) × 모든 피해 배수의 곱)`.
- 방어막 증가: `최종 피해 × Clamp01(전환율 override 또는 R + 전환율 delta 합계)`.
- 은빛 가호는 기본 전환율에 100%를 더하는 것이 아니라 **전환율을 1로 덮어쓴다**.
- 우선순위: 기름 바른 도끼 10 → 눈 가리고 때리기 20 → 일반 배수/도발 200. 덮어쓰기 이후에도 배수가 적용된다.
- 연속 베기는 현재 2회의 별도 피격이 아니라 피해 배수 ×2다. 흰개미는 피해 계산기를 거치지 않고 나무 HP를 직접 차감한다.
- SO의 `oncePerDay`는 코드에서 일일 초기화/마을 단계 진입과 연결된다. 게임에는 하루 안의 여러 `CurrentWave`가 있으므로 CSV의 “웨이브당”과 같은 의미라고 가정하지 않는다.
- `ThisTurn` 상태는 소유자 공격 처리 후 `TickTurnEnd`에서 제거된다. `NextTurn`은 2로 생성되지만 일반 턴 감소 분기가 없고 도발·저주 자체의 소진에 의존한다.

## 4. 공통 QA

- [ ] **COM-01 / P0** 각 아이템을 정상 사용한다. 비용은 표의 값만큼 1회 차감되고 해당 UID만 제거되며 효과·사용 횟수·알림이 1회 반영된다. 다른 슬롯은 보존된다.
- [ ] **COM-02** 비용 C에 대해 기력 C-1/C/C+1을 준비한다(0코스트는 기력 0). 부족 시 경고와 함께 슬롯·기력·효과·제한 모두 유지되고, 정확히 C면 사용 가능하다.
- [ ] **COM-03** 남의 턴·밤·마을 업그레이드 중 사용한다. 차단 사유가 맞고 소모/효과가 없다. 특히 업그레이드 구간은 DAY 판정만으로 통과하지 않는지 확인한다.
- [ ] **COM-04 / P0** 연타, 긴 지연 중 중복 클릭, 공격 확정과 동시 사용, 턴 타임아웃 직전 사용을 시험한다. 하나의 UID로 비용·효과가 중복되거나 다음 턴으로 잘못 넘어가지 않는다.
- [ ] **COM-05** 턴 제한 아이템 복수 소유 시 같은 턴 두 번째 사용을 막고 다음 자기 턴에 해제한다. 다른 플레이어의 사용 제한은 독립적이다.
- [ ] **COM-06** 하루 제한 아이템은 하루 중간 웨이브와 밤 경계를 각각 통과시켜 재사용 가능 시점을 기록한다. CSV “웨이브당 1회”와 불일치하면 ISSUE-04로 연결한다.
- [ ] **COM-07** 게임 제한 아이템은 다음 날에도 차단되며 새 매치/재대전에서는 초기화된다. 이전 방의 제한·미션 상태가 남지 않는다.
- [ ] **COM-08** 제한 없는 상태 아이템을 2개 사용한다. 효과 중첩과 UI 중첩 수가 일치한다. 현재 상태 시스템은 같은 ID도 추가하므로 배수 아이템의 중첩은 곱셈이다.
- [ ] **COM-09 / P0** Master와 비Master가 각각 사용하고 AI도 지원 아이템을 사용한다. 대상, 수치, 턴 진행 결과가 모든 클라이언트에서 일치한다.
- [ ] **COM-10 / P0** 사용 처리 도중 연결 종료/Master 변경 후 슬롯·기력·효과·제한을 대조한다. 중복 처리·효과 소실·진행 중단 여부를 기록한다.
- [ ] **COM-11** 빈 슬롯·잘못된 슬롯·유효하지 않은 UID/아이템 요청은 변경 없이 거절된다. 예외로 다음 사용이 막히지 않는다.
- [ ] **COM-12 / P2** KR/EN에서 이름·설명·비용·등급 색·아이콘·툴팁이 같은 ID를 가리킨다. 누락 키, CSV 열 밀림, 긴 문구 잘림을 확인한다.
- [ ] **COM-13 / P2** 성공/실패 사용 시 슬롯 UI, 상태바, 사용 알림, VFX/SFX, 전투 로그가 실제 판정과 맞는다. 거절된 사용이 성공 연출을 내지 않는다.
- [ ] **COM-14** 턴 제안/상점 구매로 아이템을 얻는다. 만석이면 기존 아이템/골드가 유지되고 제안 외 아이템을 받을 수 없다. 신규 UID가 중복되지 않는다.
- [ ] **COM-15** 5000은 일반 제안·상점에 나오지 않는다. AI 모드에서 3001·4006은 양측 제안·상점에서 제외된다. 3001을 한 번 획득한 사용자는 이후 제안/상점에서 다시 받지 않는다.

## 9. 조합·시간 경계 회귀

- [ ] **CROSS-01** 도발×날 갈기×연속 베기: D=100이면 피해 390. 은빛 가호까지 있으면 방어막 +390. 실제 최종 피해와 누적 피해를 대조한다.
- [ ] **CROSS-02** 첩자+산성비: B=1000 → 낮 산성비로 500 → 밤 첩자로 350. 밤/낮 순서와 중복 발동을 구분한다.
- [ ] **CROSS-03** 강탈+산성비 순서 비교: A=100/B=1000에서 강탈→산성비는 A400/B350, 산성비→강탈은 A250/B350. 이전 값으로 계산하는 동기화 지연 오류가 없다.
- [ ] **CROSS-04** 저주→정화→공격 시 본래 R. 첩자→정화→밤이면 반감 없음. 흰개미는 소유자가 정화했을 때만 제거되는지 확인한다.
- [ ] **CROSS-05 / P0** 흰개미/기부/회복/도박의 HP 변경과 정상 공격이 같은 경계에 실행되어도 HP 업데이트 유실, 결과 중복, 턴 중단이 없다.
- [ ] **CROSS-06** 상태 중첩 후 일부 소진·정화 시 상태바 중첩 수/실제 목록이 함께 갱신된다. 같은 statusId 제거 방송이 남은 중첩 표시를 모두 지우지 않는지 확인한다.
- [ ] **CROSS-07** 하루 마지막 선공/후공과 타임아웃 자동 공격에서 ThisTurn·NextTurn·UntilWaveEnd 수명 및 사용 제한이 동일한 기준으로 정리된다.
- [ ] **CROSS-08** PvP의 Master/비Master, AI 상대 양방향으로 동일 효과를 대조한다. AI 모드 제외 아이템(3001·4006)은 자연 획득 차단을 검증하고 정상 플레이 사용 케이스는 해당 없음으로 기록한다.

## 10. 소스에서 확인한 불일치·우선 확인 위험

아래는 플레이 재현 결과가 아니다. `확정 차이`는 파일 간 차이 또는 직접 분기 확인, `위험`은 실행 검증이 필요한 추론이다. 해결 전 기획 값 또는 구현 결함을 명시해서 케이스 판정을 남긴다.

| 이슈 | 구분 | 근거와 영향 | 연결 |
|---|---|---|---|
| ISSUE-01 | 확정 연결 부재 | 1007 SO effects=[]이며 ItemHandlingSystem의 해당 ID 특수 분기가 없음. 확인한 사용 경로에서는 8기력 소모 후 콤보 효과 없음 | DMG-18 |
| ISSUE-02 | 확정 차이 | CSV 연속 베기는 공격 효과 2회, 구현은 multiplier×2. 회당 트리거·연출이 필요한지 확정 필요 | DMG-03 |
| ISSUE-03 | 확정 차이 | 응급 수액 CSV +200, SO floatValue1=1000 | REC-01 |
| ISSUE-04 | 확정 차이 | 제물·정화 CSV는 웨이브당, SO oncePerDay. OnWaveEnd는 이름과 달리 마을 업그레이드 단계 시작 쪽에서 호출됨. 기력 이월도 CSV 다음 턴과 실제 다음 날 수입 차이 | COM-06, REC-06 |
| ISSUE-05 | 소모 위험 | 3001 oncePerGame=0. 일반 사용에서 선차감/슬롯 삭제 후 ReserveMissionForNextDay가 재사용 거절. 자연 재획득은 필터로 막지만 추가 소유·도난 등의 경로 확인 필요 | REC-09 |
| ISSUE-06 | 조기 소진 위험 | ResolveRatio의 OnDamageConvert에는 isPreview=true 전달이 없고 GIM_CURSE가 remainingTurns=0 설정. 실제 공격 전에 미리보기로 저주가 없어질 수 있음 | GIM-18 |
| ISSUE-07 | 설정 미사용 | 1006 bypassConversion=1이나 DamageResolver는 해당 값을 읽지 않음. 1005는 bypassConversion=0이어도 HP 직접 차감으로 전환 없음 | DMG-11,16 |
| ISSUE-08 | 상한/하한 확인 필요 | 회복·회복주의 즉시 처리에 최대 HP/기력 clamp 없음. 기부는 치사 방지 주석 처리 및 마을 HP 하한 clamp 없음 | REC-02,04, GIM-26 |
| ISSUE-09 | 태그 범위 차이 | 정화는 의미 해석 대신 Negative 비트만 제거. 흰개미에는 Negative가 있고 감산 피해 아이템에는 없음 | GIM-28~30 |
| ISSUE-10 | 아이템 유실 위험 | RPC_SteelItem은 원 소유자 슬롯부터 삭제한 뒤 도둑의 빈 슬롯 삽입을 시도. 만석일 때 되돌리는 코드 없음 | GIM-06 |
| ISSUE-11 | 수명 위험 | NextTurn은 초기 2이나 TickTurnEnd 감소 대상이 아님. 미발동 도발/저주 지속과 미리보기 소진을 함께 확인해야 함 | GIM-14,18, CROSS-07 |
| ISSUE-12 | 권한/중복 처리 위험 | 제물/도난 RPC에 일반 사용과 같은 송신자·턴·진행 상태 검증이 보이지 않음. 일반 사용도 CAS 성공 확인 전에 효과 진행. 정상 입력 연타와 재전송에서 검증 필요 | COM-04, DEF-10, GIM-06,24 |

원격 제물 선택 UI는 `ItemSelectionController.SetItemSelectionActive` 내부에서 대상 플레이어에게 RPC를 보내는 경로가 확인되었다. DEF-09는 이 전달 경로의 실제 동작을 검증하는 회귀 항목이다.
