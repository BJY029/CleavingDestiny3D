# 빠른 F 두 번 입력 후 이동 잠금 수정

## 원인

`NewPlayerAnimation`은 Idle/Loco → HitReady_Start → Hit_3H 순서로 타격한다. 빠른 두 번째 F의 공격 확정이 Animator의 첫 준비 상태 평가보다 먼저 도착하면, 기존 `RPC_PlayHit()`가 HitReady를 false로 바꿔 준비 상태 진입 경로를 닫았다. Idle에는 Hit 트리거만으로 타격에 진입하는 경로가 없었다.

기존 피해 요청은 애니메이션 상태와 별개인 지연 작업이어서 실행됐지만, 타격 상태의 종료 알림은 발생하지 않았다. 그 알림에서만 해제하던 `WhileAnimation`이 true로 남아 이동과 시점을 계속 잠갔다.

수정 전 실제 플레이어 F 처리 메서드를 같은 프레임에 두 번 호출해 재현했다. 4초 뒤에도 `Idle=true`, `WhileAnimation=true`, `inputLocked=true`, `attackRequestSent=true`였다.

## 수정

- 확정된 공격을 Animator에 보낼 때 HitReady를 유지해 준비 상태 진입을 보장한다. Hit_3H 진입을 기존 상태 알림 Behaviour가 알려주면 준비 플래그를 해제하고 타격음·이펙트·피해 요청 지연을 시작한다.
- 타격 상태 종료 시 진행 중인 나무 공격만 정리한다. 준비·공격 중 플래그, 임시 피해 값, 게이지를 함께 정리한다.
- 종료 알림이 누락되더라도 확정 후 3초가 지나면 나무 공격 잠금을 정리한다. 공격별 버전으로 이미 완료한 공격의 복구 작업이 뒤늦게 실행되는 것을 막는다.
- 복구는 나무 공격 상태만 정리한다. 실제 입력 활성화는 기존 Update의 메뉴·미니게임·마을 페이즈 검사에 맡긴다. 서버의 중복 피해 방지와 별도 피해 복구 경로는 유지한다.

## 검증

Unity 컴파일 오류 없음. 오프라인 AI 대전에서 플레이어의 실제 F 처리 메서드를 호출해 다음을 확인했다. 테스트에서 나무 시선 조건을 설정했으며 물리 키보드·온라인 두 클라이언트 검증은 아니다.

| 조건 | 결과 |
|---|---|
| 같은 프레임에 F 두 번 | 정상 타격 후 잠금 해제, 실제 캐릭터 이동·시점 회전 확인 |
| 0.05초 뒤 두 번째 F + 추가 8회 연타 | 정상 타격 후 잠금 해제, 이동·시점 회전 확인 |
| 0.5초 뒤 두 번째 F | 기존 일반 입력도 정상, 이동·시점 회전 확인 |
| 타격 상태 진입 후 Animator를 비활성화해 종료 알림 누락 | 3초 복구 경고 1회, 4초 검사에서 잠금 해제, Animator 재활성화 후 이동·시점 회전 확인 |

각 검증 공격의 Commit/Apply/Complete는 각각 1회였다. 정상 입력 세 경우에는 잠금 복구 경고가 없었고, 강제로 종료 알림을 누락한 경우에만 경고가 발생했다. 기존 로비 `ShopUIManager.OnDestroy()`의 KeyInteractManager 부재 오류는 별도로 남아 있으며 이번 수정에 포함하지 않았다.
