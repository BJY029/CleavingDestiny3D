# AI 모드 ITEM QA 체크리스트

작성 기준: 2026-11-28 / [ITEM_QA_CHECKLIST.md](ITEM_QA_CHECKLIST.md)를 AI 모드에 맞게 재작성.

원본의 아이템별 분류와 케이스 번호를 유지했다. `AI-DMG-01`은 원본 `DMG-01`에 대응한다. **플레이 테스트 결과가 아닌 체크리스트이며 모든 항목은 미실행이다.** 원본 및 기존 AI 판단 중심 QA 문서는 변경하지 않는다.

## 1. 실행 및 판정 방법

- 대상은 **사람 1명 + AI 1명** 모드다. 사람이 MasterClient이며, AI는 별도 Photon Player가 없는 참가자로 처리된다.
- 단일 아이템은 **AI의 획득·사용 → 효과 → 다음 행동**을 확인한다. 상대 대상 아이템은 **사람→AI / AI→사람**을 각각 검사한다.
- 각 항목은 독립 상태에서 시작한다. 별도 조건이 없으면 인벤토리 용량8칸, 기본 전환율.30, 다른 상태 없음, 해당 아이템 사용 이력 없음으로 준비한다.
- AI 사용 시험은 마지막 낮 웨이브(`CurrentWave=2`, 최대3)에서 기력8을 준비한다. 비용 합이8을 넘는 조합은 표에 적힌 기력을 별도로 준비한다.
- AI가 아이템을 안 썼다면 판단 모니터에서 기력·예산·점수·사용 제한을 먼저 확인한다. **사용하지 않은 것과 사용 후 효과가 잘못된 것을 구분**한다. 효과 검증을 위해 임계값을 낮췄다면 별도 기록하고 시험 뒤 원복한다.
- **D는 실제 원본 공격력**이다. 아래 수치는 실제 D에 대입한다. 피해·회복·방어 변화는 해당 효과 직전과 직후로 비교하고, 평타나 다른 효과의 변화가 섞이지 않게 한다.
- P0=진행 불가·유실·중복 적용·승패 오류, P1=수치·대상·지속·제한 오류, P2=표시·연출 오류. 별도 표기가 없는 항목은 P1이다.
- 체크박스는 실행 완료 표시다. 판정은 `통과 / 실패 / 준비 차단 / 기획 확인 / 해당 없음`으로 기록한다. 현재 구현과 일치해도 기획상 정상이라는 뜻은 아니다.

**준비 도구:** ItemOffer 지정으로 다음 선택지를 예약하고, AI 판단 모니터로 선택·사용·훔치기 판단을 확인한다. 시작 인벤토리는 `PlayerManager > QA 시작 아이템`을 사용한다. 이 기능은 양측에 같은 목록을 지급한다. 현재 툴에 없는 대상별 인벤토리·HP·기력·상태·타이밍 편집은 별도 준비 수단이 필요하며, 준비할 수 없으면 차단으로 남긴다. [도구 사용법](AI_QA_TOOLS.md)

## 2. AI 모드에서 확인할 흐름

AI는 **제안 선택 → 첫 훔치기 → 자기 인벤토리 사용 → 두 번째 훔치기 → 성공 시 추가 사용 → 공격** 순서로 진행한다. 아이템 사용만 확인하지 말고 이후 공격과 턴 종료까지 이어지는지 확인한다.

- 일반 아이템 사용 임계값은 프리팹 기준 **30점**, 훔치기 임계값은 **50점**이다. 기력8일 때 정상 예산은 wave0/1/2에서 **3/4/8**이다. 위기 상황에서는 전액 예산을 사용할 수 있다.
- 최종 피해는 `RoundToInt((덮어쓰기 원본 또는 D) × 피해 배수)`다. 방어막 증가는 `최종 피해 × Clamp01(전환율 override 또는 기본 전환율 + delta)`이며, 실제 구현은 **override를 정한 뒤 delta를 더한다**.
- 은빛 가호 단독은 전환율1, 저주와 함께 있으면 실제 계산상 **1-.15=.85**다. AI의 예측 경로가 실제 계산과 같은지도 확인한다.
- 밤 마을 피해는 `Max(0, 나무 공격력 × 마을 피격 배수 - 방어막 - 기본 방어력)`이다. 밤 직전 값을 사용한다.
- 하루는 기본3웨이브다. ‘하루1회’와 ‘턴1회’를 구분한다. 나무를 파괴한 현재 턴 주체는 패배하므로 강한 공격을 무조건 좋은 선택으로 보지 않는다.
