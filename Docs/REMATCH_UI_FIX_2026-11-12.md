# 게임 진행 후 로비 재매칭 UI 수정

## 재현과 원인

AI 경기 진입 후 기존 GameExitHandler 퇴장 경로로 로비에 돌아와 온라인 매칭을 시작했다. 로딩 패널은 켜졌지만 취소 버튼이 비활성 상태였고, 보조 문구에 이전 `로딩 중...Done!`가 남았다. 별도 페이드도 완전히 검은 상태로 남는 경우를 확인했다.

- SceneLoader의 LoadingCanvas는 DontDestroyOnLoad로 유지된다. 경기 시작 때 숨긴 취소 버튼을 다음 검색에서 다시 켜지 않았다.
- 씬 전환과 매칭 검색이 같은 패널을 사용하면서 보조 문구·타이머·크기 상태를 명시적으로 복구하지 않았다.
- 종료된 텍스트 애니메이션이 finally에서 이전 문구를 공유 UI에 다시 기록했다. 이전 로비 컨트롤러의 작업과 버튼 리스너도 명시적으로 정리하지 않았다.

## 변경

- SceneLoader에 매칭 화면 초기화 경로를 추가했다. 검색 시작마다 취소 버튼 표시·클릭 가능 상태, 타이머와 TimerBG, 패널 크기, 문구를 복구한다.
- 씬 로딩에서는 취소 버튼과 타이머 그룹을 숨기고 씬 로딩 문구만 사용한다. 패널을 닫으면 이전 문구와 타이머 값을 비운다.
- 취소·경기 시작·컨트롤러 파괴 때 검색 타이머와 텍스트 작업을 취소한다. 취소된 작업은 이전 문구를 다시 쓰지 않는다.
- 로비 컨트롤러가 파괴될 때 공유 취소 버튼에 등록한 두 리스너만 제거한다.
- 로비 단일 씬 로드 완료 시 기존 검은 페이드를 해제한다. 마을 등 Additive 전환은 건드리지 않는다.
- 중복 검색 클릭을 차단하고, 취소 후 늦게 도착한 일반 매칭 방 입장 응답은 방에서 나가도록 처리했다. 친구 방 시작 규칙은 유지한다.

## 확인한 결과와 한계

- Unity 컴파일 오류 없음.
- 수정 후 실제 경기에서 공격을 진행한 뒤 기존 퇴장 경로로 복귀했다. 검은 페이드를 의도적으로 켠 조건에서도 로비 복귀 시 FadeClear=true를 확인했다.
- 재매칭 UI에서 취소 버튼 표시·interactable=true, 타이머 표시, 보조 문구 빈 값·비표시를 확인했다. 이전 `Done!` 문구 없이 상대 대기 문구와 타이머가 표시되는 것을 화면으로도 확인했다.
- 로비 복귀 후 공유 취소 버튼의 런타임 리스너는 2개였다.
- Computer Use의 포인터 입력 시도는 SendInput 오류 87이 발생해 물리 클릭 검증의 통과 근거로 사용하지 않았다.
- 추가 반복 취소·즉시 취소의 자동 검증 도구 호출은 취소되어 완료되지 않았다. 마지막 Editor 상태 조회는 LobbyScene의 Play Mode 종료 전환 상태였다.
- 경기 결과 정산을 포함한 완주·두 클라이언트 대전·실행 파일 재빌드는 수행하지 않았다.
- 퇴장 시 기존 KeyInteractManager 파괴 순서 오류, StoryCreditController의 `story ended` 오류 로그, 종료 후 AI 작업의 NullReferenceException도 관찰했다. 이번 공유 UI 초기화 수정과 구분하며 해결했다고 판정하지 않는다.
